# GrowLog — Notion + трекер фокуса (проектная спецификация)

> Рабочее имя, переименуй как хочешь. Держи этот файл в корне репозитория —
> Claude Code будет читать его как постоянный контекст между сессиями.

## 1. Что это

Локальное веб-приложение. Пользователь вводит активность («учу программирование»),
жмёт Start → включается таймер и по центру растёт дерево (визуальный прогресс).
Таймер видно всегда, в компактном виде. По завершении сессия падает в лог
повседневных активностей: точное затраченное время + чеклист выполненных целей
(«выучил циклы в Python») + заметка.

Ядро — это связка двух метафор: **Notion** (структурированная база активностей,
цели, заметки) + **Forest** (фокус-таймер с растущим деревом).

## 2. Формат и стек (и почему так)

**Формат: локальное веб-приложение (браузер), устанавливается как PWA.**

Почему не Telegram-бот / нативная мобилка / Electron:
- дерево + крупный таймер идеально живут и рендерятся в браузере;
- нет бэкенда и деплоя — Claude Code за один заход поднимает рабочий прототип;
- PWA даёт иконку на телефоне и десктопе + офлайн;
- позже без переписывания оборачивается в Tauri (компактный таймер поверх
  других окон) или получает реальную синхронизацию с Notion.

**Стек:**
- `Vite + React + TypeScript` — быстрый скелет, TS помогает Claude Code не косячить
- `Tailwind CSS` — быстрая вёрстка
- `Dexie.js` (IndexedDB) — локальная «Notion-база» активностей и сессий
- `Zustand` — состояние таймера (лёгкое, без бойлерплейта)
- `date-fns` — форматирование времени и дат
- Дерево — процедурный/staged **SVG** (без внешних ассетов, полный контроль)

## 3. Про Notion

Notion — только ориентир по ощущению (структурированная база активностей, цели,
заметки). Реальная интеграция или синхронизация с Notion НЕ нужна. Всё хранится
локально в браузере (Dexie/IndexedDB). Никакого бэкенда и Notion API.

## 4. Модель данных

```ts
type Session = {
  id: string;              // uuid
  activityId: string | null; // ссылка на категорию (Activity), опционально
  activityName: string;    // имя на момент сессии (денормализовано)
  startedAt: number;       // epoch ms
  endedAt: number | null;
  durationSec: number;     // фактическое время с учётом пауз
  goals: Goal[];
  note: string;
  date: string;            // YYYY-MM-DD, локальная дата начала (для группировки)
};

type Goal = {
  id: string;
  text: string;            // "выучил циклы в Python"
  done: boolean;
};

type Activity = {          // категория / долгосрочное дерево
  id: string;
  name: string;
  emoji: string;
  color: string;
  totalSec: number;        // суммарное время → рост персонального дерева
  createdAt: number;
};
```

**Состояние живого таймера** (в памяти + зеркало в localStorage для устойчивости):

```ts
type RunningTimer = {
  activityName: string;
  startedAt: number;       // когда запустили
  accumulatedSec: number;  // время до последней паузы
  lastResumeAt: number | null; // null когда на паузе
};
// elapsedSec = accumulatedSec + (running ? (Date.now() - lastResumeAt)/1000 : 0)
```

Ключевая деталь: `startedAt` и `accumulatedSec` пишем в localStorage. Если вкладку
перезагрузили — таймер восстанавливается и показывает точное время, ничего не
теряется.

## 5. Экраны

1. **Focus (главный).** Выбор из списка активностей или ввод новой → Start.
   По центру крупный, но компактный таймер + растущее дерево. Кнопки Пауза / Стоп.
   При скролле таймер прилипает к верху узкой полоской (тот самый «компактный вид
   на видном месте»).
2. **Finish modal** (по Стоп). Показывает фактическое время. Чеклист целей:
   добавить пункты, отметить сделанные. Поле заметки. Кнопка Сохранить → пишет
   `Session` в Dexie и прибавляет время к `Activity.totalSec`.
3. **Log — повседневные активности.** Список, сгруппированный по дням. Каждая
   запись: активность + точное время + отмеченные цели + заметка. Клик →
   редактирование, свайп/кнопка → удаление.
4. **(v2) Garden.** Все деревья/сессии сеткой.
5. **(v2) Stats.** Суммарно по активностям, стрик по дням.

## 6. Дерево

- **MVP:** 5 стадий (seed → росток → саженец → молодое дерево → цветение),
  переключаются по прогрессу. Прогресс = `elapsedSec / целевое_время` (напр. 25 мин)
  ИЛИ бесконечный рост: каждые N минут — новая ветка/стадия.
- **v2:** плавный процедурный SVG — ветви «прорисовываются» через `stroke-dashoffset`,
  листья появляются fade-in; либо Lottie со scrub по прогрессу.
- **Долгосрочно:** у каждой категории (`Activity`) своё дерево, растущее по
  накопленному `totalSec` — видно прогресс за недели, а не только за сессию.

## 7. Фазы (майлстоуны для вайбкодинга)

Делай по одной, коммить после каждой.

- **Phase 0 — Scaffold.** Vite + React + TS + Tailwind. Роутинг Focus / Log. Пустой layout.
- **Phase 1 — Timer core.** Start / Пауза / Стоп, точное время, устойчивость к
  перезагрузке (localStorage-зеркало).
- **Phase 2 — Активности.** Ввод новой + выбор из списка. Хранение `Activity` в Dexie.
- **Phase 3 — Дерево.** Staged SVG, растёт по elapsed.
- **Phase 4 — Finish modal + сохранение.** Чеклист целей + заметка → `Session` в Dexie.
- **Phase 5 — Log view.** Группировка по дням, редактирование/удаление.
- **Phase 6 — Polish.** Липкий компактный таймер, Notion-подобная типографика,
  пустые состояния, тёмная тема.
- **Phase 7 (опц.).** Stats, Garden, PWA-установка, экспорт в JSON.

## 9. Правила вайбкодинга

- Один майлстоун за раз. После каждого — запусти, проверь руками, потом коммить.
- Всегда проси сначала план, потом код («покажи план, не пиши код пока не подтвержу»).
- Держи SPEC.md в корне — обновляй его, когда меняешь решения по проекту.
- Если что-то поехало — не чини вслепую, откатись на последний рабочий коммит.
- Названия из модели данных (`Session`, `Activity`, `Goal`) используй везде
  одинаково — так Claude Code не путается между файлами.

## 10. Раздача другу (деплой)

У каждого свой отдельный трекер по одной ссылке. Общих данных и синхронизации нет,
бэкенд не нужен — приложение статическое.

Шаги (когда MVP готов):
1. Пушишь репозиторий на GitHub.
2. Подключаешь его к Vercel (или Netlify / Cloudflare Pages) — бесплатно,
   деплой на каждый пуш. Получаешь ссылку вида `growlog.vercel.app`.
3. Кидаешь ссылку другу. Он открывает, «Установить приложение» (PWA) — иконка
   на телефоне/десктопе, работает офлайн.

Важно: данные каждого лежат в его браузере (IndexedDB). Почистил данные браузера —
история пропала. Поэтому **экспорт в JSON (Phase 7) — это и бэкап, и способ
перенести своё состояние** на другое устройство. Стоит поднять его пораньше, если
история для тебя важна.
